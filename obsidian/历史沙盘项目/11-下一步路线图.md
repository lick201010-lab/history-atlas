# 下一步路线图

## 优先级判断

当前项目已经上线，数据、地图交互、移动端基础布局和 14 个 GLB 覆写都已成型。下一步不要再写“什么都做”的大清单，而要按真实阻塞顺序推进。

## P0：建立 14 个 GLB 的地图视角 QA

目标：

- 不再靠主观描述判断“这个奇观好不好”。
- 对已接入的 14 个 GLB 做统一截图、统一评价、统一风险排序。

任务：

- 用 `docs/GLB_ASSET_BASELINE.md` 作为资产清单。
- 对每个 GLB 在地图中做近景 / 45° 俯视 / 贴地低角度三类截图。
- 记录：轮廓辨识度、体积大小、贴地状态、是否穿模、是否像文化建筑而不是普通积木。
- 重点关注 `chichen-itza`，因为自动审计已经提示三角面偏低。

说明：

这一步适合 Codex 做，因为它是验收和质量归档，不是大批量建模。

## P1：精修下一批低质量 GLB

目标：

- 先修最明显的问题资产，而不是一次性新增 30 个。

候选：

- `chichen-itza`：低三角面，可能轮廓太粗。
- 根据 P0 截图 QA 再选 2 个最弱资产。

说明：

这一步适合 Claude 主做单个资产脚本，Codex 验收 `audit:glb`、地图截图和视觉质量。

## P1：把边界方法扩到更多重点文明

目标：

- coastline-aware 不再只停留在少数代表项。

任务：

- 选择下一批高优先文明。
- 按 `docs/BOUNDARY_REFINEMENT_METHODOLOGY.md` 做 phase 化和多包络裁切。
- 同步 `sourceNote` / `accuracyNote`。

说明：

这一步适合 Claude 批量做，Codex 抽查和验收。

## P2：补引用与可信度体系

目标：

- 让重点文明、重点边界、重点建筑开始具备可追溯说明。

任务：

- 先从样板文明和样板奇观开始。
- 给 event / boundary / landmark 补更规范的来源字段。
- 形成轻量引用规范。

说明：

当前项目最大短板已经从“没功能”转向“可信度不足”。

## P3：性能与资源加载优化

目标：

- 在不牺牲当前体验的前提下给后续扩展留余地。

任务：

- 评估 MapLibre / Three / JSON / GLB 的增长趋势。
- 判断是否需要更明确的懒加载。
- 评估移动端 GPU 和内存压力。

说明：

这一步重要，但不应早于视觉与内容基线稳定。

## 当前不建议优先做的事

- 不建议重新摇摆到 globe 或其他地图引擎。
- 不建议在 atlas 主题上继续激进探索。
- 不建议为了“更精细”盲目批量堆更多 GLB。
- 不建议一次性让 Claude 做 30 个奇观，质量会不可控。

## 推荐执行顺序

1. 完成 14 个 GLB 地图视角 QA。
2. 精修 `chichen-itza` 或 QA 中最弱的 1 个资产。
3. 扩下一批重点文明边界。
4. 补重点边界 / 奇观的来源说明。
5. 做性能与懒加载评估。
