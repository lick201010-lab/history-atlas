# 部署与运维

## 线上信息

- 生产地址：`https://atlas.ckl.hk`
- 服务器：阿里云 ECS
- IP：`47.237.181.181`
- 系统：Ubuntu 24.04 LTS
- Web 服务：Caddy
- 静态目录：`/opt/history-atlas/dist`
- 同一台服务器还运行 lottery 项目。

## 部署方式

当前采用本地 Windows 构建，然后上传 `dist/`：

```bash
npm run deploy
```

该命令会：

1. 检查本地工具。
2. 运行 `npm run check`。
3. 构建 `dist/`。
4. 通过 `scp` 上传到服务器。
5. 修正远端文件权限。
6. 校验线上首页。
7. 校验 SPA fallback。
8. 校验线上 JS/CSS chunk。

## 为什么不在服务器构建

服务器内存较小，Vite + Rollup + MapLibre + Three 构建峰值可能吃紧。因此优先本地构建再上传。

## Caddy 配置思路

`atlas.ckl.hk` 使用单独 site block：

```caddy
atlas.ckl.hk {
    root * /opt/history-atlas/dist
    file_server
    try_files {path} /index.html
    encode gzip zstd
}
```

Caddy 自动签发 Let's Encrypt 证书，不需要 Nginx 或 certbot。

## 运维注意事项

- 不要破坏 lottery 项目的 `/opt/lottery-analysis`。
- 不要随意改 Caddyfile，除非明确需要。
- 部署脚本不 reload Caddy，只更新静态文件。
- 如果改域名或 Caddy 配置，才需要服务器上执行 `caddy validate` 和 `systemctl reload caddy`。

## 已知限制

- 当前上传方式不是 `rsync --delete`，旧 hashed assets 可能残留。
- 这对 MVP 影响不大，但后期可改成更干净的同步脚本。
- 地图瓦片是外部资源，线上访问体验会受网络影响。
