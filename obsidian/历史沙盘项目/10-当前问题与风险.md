# 当前问题与风险

## 视觉清晰度

古地图方向有质感，但容易变模糊。需要在“历史质感”和“信息清晰”之间找到平衡。

风险：

- sepia / parchment 色调过重会降低边界和文字可读性。
- 地形纹理过强会干扰文明边界。
- 海洋如果保留 DEM/hillshade 噪声，会出现“海里有山”的错觉。

## 边界贴合

用户对边界的期待是贴近真实国家/海岸线，而不是低顶点示意形状。

风险：

- 只做平滑会让线变圆，但不会更真实。
- 单一凸包会跨海包住大片不应属于文明的区域。
- 历史边界本身存在争议，需要 sourceNote 和 accuracyNote。

## 3D 建筑精度

当前程序化模型仍偏符号化。圣索菲亚虽已提升，但还没有达到参考图级别。

风险：

- 程序化建模越加越复杂，收益下降。
- 真实 GLB 会增加资源体积。
- 多模型同时加载会影响性能。

## 性能

MapLibre、Three 和主应用 chunk 都较大。当前可接受，但继续增加 GLB 和边界数据后需要优化。

风险：

- 首屏加载慢。
- 移动端内存和 GPU 压力大。
- 外部瓦片服务慢时体验不稳定。

## 数据可信度

当前历史数据是 MVP 级别，适合产品展示，不适合学术引用。

风险：

- 用户可能误解为精确历史地图。
- 文明事件和边界缺少正式引用。
- 不同历史时期的边界应拆分更多 phase。

## 工程协作

Claude 和 Codex 会交替工作，容易出现未提交改动重叠。

风险：

- 文件互相覆盖。
- 本地 ahead GitHub 太多。
- 部署版本和 GitHub 版本不一致。

应对：

- 每次先 `git status`。
- Codex 不回滚 Claude 文件。
- 大任务让 Claude 做，Codex 验收和提交清晰分组。
