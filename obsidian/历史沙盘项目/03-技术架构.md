# 技术架构

## 技术栈

- React 18：UI 组件和顶层状态
- Vite 7：开发服务器与生产构建
- MapLibre GL JS 4.7：底图、DEM、边界图层、交互拾取
- Three.js 0.160：MapLibre custom layer 内的 3D 建筑
- 本地 JSON 数据：文明、边界、地标、时代
- Caddy v2：线上静态资源服务和 HTTPS

## 运行模型

这是一个纯前端静态网站，没有后端 API。构建后所有核心业务数据打包在前端资源中，运行期外部依赖主要只有地图瓦片和 DEM。

## 当前架构状态

- `globe.gl` 路线已被放弃，当前主线回到 MapLibre 平面地图。
- 地图主容器是 `MapScene.jsx`，通过 MapLibre 管边界和交互，通过 custom layer 接 3D 建筑。
- 程序化建筑与 GLB 覆写并存，先保证可显示，再异步替换为高质量资产。
- 当前本地分支正在做 dark 主题装裱框和边界重绘细化，这些改动仍未提交。

## 组件职责

- `src/App.jsx`
  - 顶层编排
  - 年份、图层、筛选、对比、选中文明/建筑状态
  - 当前新增了 dark 主题地图装裱框 DOM
- `src/components/MapScene.jsx`
  - 初始化 MapLibre
  - 管理边界 source / layer / hover / click
  - 接入 `createBuildingLayer.js`
  - 当前本地改动包含：
    - `renderWorldCopies: false`
    - 提高 `maxPitch`
    - 右侧 `setPadding`
    - `smoothBoundaryCollection(...)`
    - `dynasty-territory-casing`
    - 主题切换后延时 `map.resize()`
- `src/map/mapStyle.js`
  - 主题 preset
  - dark / atlas 边界 paint 逻辑
  - 当前本地改动重点是 dark 主题 glow / casing / line 的重新分工
- `src/map/createBuildingLayer.js`
  - procedural mesh builder
  - GLB 覆写映射和异步加载
  - 材质角色和主题同步

## 数据与脚本层

- `src/data/dynasties.json`：43 个文明
- `src/data/boundaries-simplified.json`：89 个边界 feature
- `src/data/landmarks.json`：30 个地标
- `src/data/eras.json`：8 个时代
- `scripts/validateHistoricalData.mjs`：结构和引用完整性校验
- `scripts/refineByzantineBoundary.mjs`：拜占庭边界专项脚本
- `scripts/buildHagiaSophiaGlb.mjs` 等：单奇观 GLB 生成脚本
- `scripts/lib/wonderKit.mjs`：可复用奇观建模原语

## 构建与发布

- `npm run validate:data`
- `npm run build`
- `npm run check`
- `npm run deploy`

当前发布模式不是服务器拉源码构建，而是本地 Windows 构建后把 `dist/` 通过 `scp` 上传到阿里云。

## 线上部署架构

- 域名：`atlas.ckl.hk`
- 静态目录：`/opt/history-atlas/dist`
- Caddy 负责：
  - 静态资源
  - SPA fallback
  - 自动 HTTPS
- 服务器与 `lottery-analysis` 共机，但 history-atlas 不依赖其后端

## 当前架构约束

- 不能依赖服务器高内存构建
- 不应让 atlas 主题被 dark 主题试验误伤
- 数据 JSON 不应被频繁手改破坏
- 地图视觉修改必须考虑 MapLibre 容器 resize 和高 pitch 约束

## 当前主要架构风险

- MapLibre 和 Three 依旧是较重依赖
- 边界 feature 增长后，GeoJSON 体积和 setData 成本会继续上升
- GLB 资产数量继续增加后，需要更明确的懒加载与体积预算
- 当前未提交 UI 改动尚未通过真实浏览器长期验证
