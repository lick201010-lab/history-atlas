# 技术架构

## 技术栈

- React 18：界面状态和组件。
- Vite 7：本地开发和构建。
- MapLibre GL JS 4：地图、矢量图层、3D terrain。
- Three.js：MapLibre custom layer 中渲染 3D 建筑。
- 本地 JSON：文明、边界、建筑、时代叙事数据。
- Caddy：线上静态文件服务和 HTTPS。

## 运行模式

这是一个纯前端静态网站，没有后端服务。数据都在 `src/data/` 内，构建后打包进前端资源。地图瓦片和 DEM 依赖外部服务。

## 组件职责

- `App.jsx`：应用主状态，年份、主题、筛选、选中文明、选中建筑。
- `MapScene.jsx`：地图初始化、边界图层、点击/hover 交互、相机控制。
- `Timeline.jsx`：时间滑块和关键年份标记。
- `InfoPanel.jsx`：当前年份文明/建筑列表。
- `LayerControls.jsx`：图层开关和搜索。
- `FilterPanel.jsx`：区域和标签筛选。
- `ComparePanel.jsx`：最多两个文明对比。
- `LandmarkCard.jsx`：建筑档案卡片。
- `Starfield.jsx` / `CloudLayer.jsx`：氛围层。

## 地图层级

1. 星空和背景氛围。
2. MapLibre 地图底图。
3. DEM 3D 地形和 hillshade。
4. 海洋/陆地视觉策略。
5. 文明 territory fill。
6. 文明边界线、glow、casing、hover。
7. Three.js 建筑 custom layer。
8. HTML HUD 和信息面板。

## 资产路径

- `public/models/hagia-sophia.glb`：圣索菲亚 GLB 资产。
- `public/`：构建时会原样复制到 `dist/`。
- `dist/`：生产构建产物。

## 构建与校验

常用命令：

```bash
npm run dev
npm run validate:data
npm run build
npm run check
npm run deploy
```

## 架构风险

- MapLibre、Three、主入口 chunk 都偏大，需要长期关注首屏体积。
- DEM 和地图瓦片依赖外部服务，网络不佳会影响体验。
- 3D 建筑如果全部升级为 GLB，需要做资源体积预算和懒加载。
- 复杂边界数据会增加 JSON 体积，需要分区加载或压缩策略。
