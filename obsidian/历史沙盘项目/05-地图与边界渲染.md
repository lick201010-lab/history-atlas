# 地图与边界渲染

## 当前地图引擎结论

当前主线明确是 MapLibre GL JS，不再走 `globe.gl`。地图空间感主要靠：

- 3D terrain
- 高俯仰相机
- 山脉视角
- 边界发光和 casing
- 3D 建筑叠加

## 当前 dark 主题地图方向

本地未提交改动表明地图正在朝这个方向收敛：

- 地图主体内缩成一张“被装裱的星图卡”
- 四周留出星空边距
- 文明边界通过 glow + casing + 亮线强化疆域感
- atlas 主题保持冻结，避免被新风格污染

## 当前边界系统的三层问题

### 1. 数据层

边界本体仍然是粗历史范围，不是学术级 GIS 边界。部分 feature 已升级为 `coastline-aware-rough`，但大量文明仍停留在更粗略层级。

### 2. 几何层

低顶点折线在放大后会显得廉价，所以当前本地新增了 `src/map/smoothBoundaries.js`，用运行时 Chaikin 平滑来改善观感。

### 3. 视觉层

边界在 dark 主题下不再主要依赖大面积填充，而是：

- 极淡 territory fill
- 外侧 glow
- 下方深色 casing
- 顶部清亮 line

这样可以在复杂地形上把边界“抬”出来。

## 当前本地分支中的关键边界改动

### `smoothBoundaryCollection(...)`

- 运行时平滑 `FeatureCollection`
- 不改 JSON
- Polygon / MultiPolygon 都支持
- 顶点少的 ring 迭代次数更多
- WeakMap 缓存避免重复算

这是典型的“几何表现层修饰”，不是数据真实性修复。

### `MapScene.jsx` 的边界层调整

- 新增 `dynasty-territory-casing`
- 给 `glow` / `casing` / `line` / `hover` 统一加 `line-join: round` 和 `line-cap: round`
- `source.setData(...)` 改为写入平滑后的 collection
- `setFilter` / `setVisibility` 已同步 casing 层

### `mapStyle.js` 的 dark 边界重绘

- glow 更宽、更亮
- line 变成更清亮的实线
- casing 用近黑藏蓝托住亮线
- zoom 越近，line 和 glow 越粗
- atlas 主题下 casing 被强制压到不可见

## 右侧视口遮挡问题

这不是边界数据问题，而是地图相机约束问题。

当前本地代码在 `MapScene.jsx` 做了：

- `renderWorldCopies: false`
- `map.setPadding({ right: ... })`
- 不使用 `maxBounds`

理由已经在 `WORK_LOG.md` 里写得很清楚：高 pitch 下 `maxBounds` 容易触发 MapLibre 黑屏。padding 是更安全的做法。

## 拜占庭样板的意义

当前拜占庭不是普通 feature，而是“方法论样板”：

- 多包络裁切
- 按陆块拆开
- 保留海岸贴合
- 内陆边做粗糙化处理，减少直线包络感

这说明项目已经形成一套边界精修方法，而不是继续手工涂几个多边形。

## 当前边界渲染的真实结论

- 运行时平滑能改善廉价折线感。
- casing 能显著提升边界可读性。
- 但如果底层边界数据本身错误，平滑不会把假边界变真。
- 所以下一步不能只做样式，还要把边界精修方法批量扩展到更多重点文明。

## 后续最有价值的边界工作

- 把 `docs/BOUNDARY_REFINEMENT_METHODOLOGY.md` 里的方法扩展到更多重点文明
- 明确哪些文明值得做三阶段 feature
- 让 README / 验收文档 / Obsidian 笔记都统一接受“89 个 feature”的现实
- 用真实浏览器截图确认新 dark 边界不是“看代码觉得会更好”
