## Runtime Fix 2026-06-07

Cocos Preview surfaced:

```text
TypeError: Cannot read properties of undefined (reading 'ALL')
```

Cause:

- `ClearFlagBit` was imported from the public `cc` entrypoint, but the sample should use `Camera.ClearFlag`.

Fix:

- `Bootstrap.ts`: `Camera.ClearFlag.SOLID_COLOR`
- `UIController.ts`: `Camera.ClearFlag.DEPTH_ONLY`

Verification:

- Runtime scripts transpile with Cocos-bundled TypeScript.
- `npm run check` passes.

## Runtime Fix 2026-06-07: 2D Batcher Isolation

Cocos Preview later surfaced:

```text
TypeError: Cannot read properties of undefined (reading 'localSetLayout')
```

Cause evidence:

- `localSetLayout` is read by Cocos Creator's 2D batcher.
- The sample's only 2D render path is the programmatic `UIController`.
- This points to a UI render batch without a valid material pass, not the 3D sandbox.

Temporary fix:

- `Bootstrap.ts` no longer attaches `UIController`.
- The sample should first prove the 3D sandbox, boundary, and landmark render path.

Follow-up:

- Rebuild UI as a Cocos prefab or platform overlay after 3D Preview passes.

## Visual Framing Pass 2026-06-07

After the runtime errors were cleared, the first visible Cocos scene was still not acceptable as a visual proof:

- the land was a full green rectangle;
- the ocean was visually hidden;
- boundaries and landmarks were too small and read as debug artifacts;
- landmark fallback models looked like plain beige blocks.

Changes made:

- `SandboxBuilder.ts` now builds land masses from Byzantine boundary rings instead of a full rectangular terrain plane.
- The ocean remains a separate large flat dark plane.
- Boundary outlines are wider and sit above the land layer.
- A subtle coast glow and relief strokes were added to improve readability without recreating full terrain yet.
- `Bootstrap.ts` now frames the camera from exported boundary and landmark bounds.
- `SandboxCamera.ts` exposes a `configure()` method for data-driven framing.
- `LandmarkLoader.ts` now scales landmarks up and provides readable fallback silhouettes for Hagia Sophia, Parthenon, and the Colosseum.
- The same changed scripts were copied to the D-drive Cocos working copy currently used by Creator Preview.
- D-drive `temp/programming` was removed so Creator recompiles the scripts.

Verification:

- C-drive Cocos scripts: TypeScript `transpileModule` OK.
- D-drive Cocos scripts: TypeScript `transpileModule` OK.
- `node mini-game/tools/exportByzantineData.mjs` OK.
- `npm run validate:data` OK.
- `npm run check` OK, with only existing Vite chunk-size warnings.
- Latest asset-db log scan found no `TypeError`, `localSetLayout`, `ClearFlagBit`, `SyntaxError`, `n.map`, or `Init asset worker`.

Remaining risk:

- Direct headless access to `http://localhost:7456/` still produced `ReferenceError: System is not defined`; evidence screenshot is `docs/cocos-qa/cocos-preview-direct-browser-system-error.png`.
- This means Creator embedded Preview is not enough for the sidecar Gate. The next validation must use a formal Cocos Web Desktop build or WeChat/Douyin developer tools.
